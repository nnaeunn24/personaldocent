1. 선정 목적
━━━━━━━━━━━━━━━━━━━━━━━━

관람객이 선호하는 정보 유형을 중심으로,
여러 정보를 결합했을 때 개별 정보를 단순히 나열하는 것보다
더 높은 설명 가치를 제공하는 Knowledge Bundle을 선정합니다.

Knowledge Bundle은 하나의 중심 설명 주제를 구성하는
Core Unit, Related Units, Semantic Relations의 조합입니다.

━━━━━━━━━━━━━━━━━━━━━━━━
2. WHAT의 정의
━━━━━━━━━━━━━━━━━━━━━━━━

VISUAL:
작품에서 실제로 관찰할 수 있는 색채, 형태, 구도,
대상, 공간적 배치와 세부 시각적 특징.

MEANING:
작품의 주제, 작가의 표현 의도, 상징,
정서적 표현 및 근거가 있는 해석.

TECHNIQUE:
재료, 안료, 붓질, 색채 운용, 제작 방식,
조형적 선택과 그에 따른 시각적 효과.

BACKGROUND:
작품의 제작 시기와 장소, 작가의 경험,
역사적·사회적·미술사적 맥락.

━━━━━━━━━━━━━━━━━━━━━━━━
3. 정보 선정 기준
━━━━━━━━━━━━━━━━━━━━━━━━

다음 기준을 종합적으로 고려하십시오.

A. Preference Relevance

Core Unit은 반드시 관람객이 선택한 WHAT에 해당해야 합니다.

B. Explanatory Complementarity

Related Unit은 Core Unit과 결합했을 때
새로운 설명 가치가 발생해야 합니다.

다음과 같은 조합을 우선적으로 고려하십시오.

- 시각적 특징과 그 특징을 구현한 표현 기법
- 표현 기법과 그로 인해 나타나는 시각적 효과
- 작품 속 대상과 그 대상의 상징적 해석
- 작가의 표현 의도와 실제 화면에서의 구현
- 제작 배경과 작품에 나타난 구체적인 특징
- 서로 대비되는 시각적 요소와 표현 방식
- 추상적인 해석과 이를 뒷받침하는 구체적 관찰

C. Artwork Specificity

다른 작품에도 쉽게 적용할 수 있는 일반적인 정보보다
현재 작품에서 구체적으로 확인할 수 있는 정보를 우선합니다.

D. Coherence

하나의 Bundle은 하나의 일관된 설명 주제를 구성해야 합니다.

서로 관계가 있다는 이유만으로
모든 정보를 하나의 Bundle에 포함하지 마십시오.

E. Non-redundancy

동일한 사실을 반복하는 Unit은 함께 선정하지 마십시오.

서로 다른 Bundle 사이에서도 정보를 중복하지 마십시오.

F. Grounding

제공된 Semantic Relation만 활용하십시오.

관계의 방향과 의미를 임의로 변경하지 마십시오.

SUPPORTED_INFERENCE는 근거 있는 연결이지만
확정적인 인과관계 또는 작가의 의도로 취급하지 마십시오.

curatorial_interpretation은 사실이나 작가의 확정적 의도가 아닌
큐레이터의 해석으로 유지하십시오.

4. 선정 규칙
━━━━━━━━━━━━━━━━━━━━━━━━

- 목표 분량이 600자 이하라면 Knowledge Bundle을 2개 선정하는 것을 우선합니다.
- 충분한 설명 가치가 있을 때만 3개를 선정합니다.
- 각 Bundle에는 Core Unit 1개를 포함합니다.
- 각 Bundle에는 Related Unit을 1~3개 포함할 수 있습니다.
- 설명 가치가 있는 관계가 없다면 Core Unit만 사용할 수 있습니다.
- 전체 Bundle에 포함된 Unit 수의 합계는 8개 이하여야 합니다.
- 다른 Bundle에서 이미 선정한 Unit을 다시 선정하지 마십시오.
- 출력하기 전에 전체 Unit 수를 직접 계산하십시오.
- Bundle의 제목과 선정 이유는 실제로 선정한 Unit의 내용과 일치해야 합니다.
- 여러 표현 기법을 무리하게 하나의 Bundle에 결합하지 마십시오.
- 하나의 정보를 충분히 설명하는 것이 많은 정보를 포함하는 것보다 중요합니다.
- 전체 Bundle에 포함되는 고유 Unit 수는 최대 8개입니다.
- Core Unit은 반드시 WHAT과 일치해야 합니다.
- Core Unit 후보도 다른 Bundle의 Related Unit으로 사용할 수 있습니다.
- 동일한 Unit을 여러 Bundle에 중복 포함하지 마십시오.

[중요: 정보 간 연결]

Related Unit은 반드시 입력에 제공된 Semantic Relation을 통해
Core Unit과 직접 또는 간접적으로 연결되어야 합니다.

간접 연결에 필요한 중간 Unit도 반드시 함께 선정하십시오.

예를 들어 다음 관계가 존재하는 경우:

A — B
B — C

A를 Core Unit으로 선정하고 C를 Related Unit으로 활용하려면
중간 Unit인 B도 함께 선정해야 합니다.

A와 C가 유사한 주제를 다룬다는 이유만으로
두 Unit을 직접 연결해서는 안 됩니다.

Relation ID는 출력하지 마십시오.
선정된 Unit 사이의 실제 관계는 시스템이 자동으로 매핑합니다.

설명 가치가 있는 관계가 없다면 Core Unit만 선정할 수 있습니다.

관계의 수를 최대화하는 것이 목적이 아닙니다.

하나의 중심 정보를 다른 정보가 구체화하거나,
설명하거나, 의미를 확장하는 조합을 우선하십시오.

목표 글자 수 안에서 충분히 설명할 수 있는 정보만 선정하십시오.

도슨트 문장 자체는 작성하지 마십시오.
